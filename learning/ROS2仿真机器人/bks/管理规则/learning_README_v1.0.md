# AI机器人项目学习教材管理说明

版本：v1.0

## 1. 目录定位

`learning/`保存基于本项目真实工程成果编写的正式学习教材，并纳入Git与GitHub管理。

```text
learning/
├── README.md
├── ROS2仿真机器人/
│   └── PU*_*.md
└── bks/
```

- `learning/ROS2仿真机器人/`：当前有效的ROS 2仿真机器人教材；
- `learning/bks/`：历史教材版本；
- `plan/`：规定学习目标、内容范围、练习和验收要求，不保存教材正文；
- `tests/evidence/`：保存人工操作、观察和学习验收证据，不保存教材正文。

## 2. 教材组成

每个PU在进入正式练习前，必须先形成一份版本化主教材。教材由以下两部分组成：

1. 教材正文，必需；
2. 外部参考资料链接，可选。

教材正文必须能够离线独立阅读，不得用一组外部链接代替讲解。

### 2.1 教材正文

正文至少包括：

- 学习目标和适用范围；
- 本项目采用的实际架构、程序包、节点和文件；
- ROS 2对象、接口、参数、QoS和TF；
- 关键功能链路和数据流；
- 只读检查或受控操作方法；
- 正常现象、常见问题及首查位置；
- 仿真实现与未来实体实现的对应关系；
- 术语表、学习总结和练习前理解检查；
- 项目内依据。

教材必须明确区分：

- 当前已经实现并通过工程测试的内容；
- 教学解释或概念模型；
- 后续实体阶段才会实现的内容；
- 阶段 2才会讨论的AI Agent内容。

### 2.2 外部参考资料

外部资料只在确有帮助时提供，优先使用：

- ROS 2 Humble官方文档；
- Nav2、SLAM Toolbox及实际第三方组件的官方文档；
- 官方源代码仓库、接口文档和发布说明。

每条外部资料至少记录资料名称、来源、适用版本、用途、链接和查阅日期。来源不明、版本不匹配或无法验证的内容不得列为正式参考资料。

外部资料与本项目实现不一致时，以当前项目代码、配置、测试证据和有效规划为准，并在教材中说明差异。

## 3. 编写与学习顺序

每个PU固定按以下顺序执行：

```text
依据学习计划确定教材范围
→ 编写并审阅完整PU教材
→ AI教员按教材顺序讲解
→ 学员提出问题并完成理解检查
→ 学员亲自执行实际练习
→ 形成学习检查与证据
```

不得在教材尚未形成或尚未讲解完毕时，直接把正式实际练习标记为完成。AI代为运行的命令只能作为演示或工程基线证据，不能替代学员人工执行。

## 4. 版本与归档

- 当前教材文件名包含版本号，例如`PU1_项目总体架构与工程资源_v1.0.md`；
- 修改教材正文时提升版本号，并将旧版移入`learning/bks/`；
- 仅修正学习证据或状态记录时，不修改教材版本；
- 教材版本、学习计划版本、证据记录和Git提交应可相互追踪；
- `docs/`中的网页原稿或参考资料不作为当前有效教材，也不上传GitHub。

## 5. 安全边界

- 教材不得授权实体机器人上电、运动、控制命令或硬件测试；
- 仿真运动练习必须使用项目已有受控入口，不得手工发布`/cmd_vel`或`/cmd_vel_raw`；
- 不在ROS 2学习教材中实现或启动AI Agent；
- 发现工程缺陷时先保存现象和证据，再按项目变更流程处理，不在教学过程中直接修改稳定基线。
