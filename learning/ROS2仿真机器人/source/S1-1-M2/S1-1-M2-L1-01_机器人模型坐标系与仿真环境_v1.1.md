## 1. 学习目标

学员应能解释Xacro如何生成URDF，Link描述什么，Joint怎样建立树，惯量与Collision为何影响物理仿真，Gazebo插件怎样把模型接到ROS 2，以及`robot_state_publisher`与Gazebo分别承担哪些TF责任。

## 3. 模型结构

`base_footprint`是地面投影根Link，不带惯量；固定关节连接`base_link`。左右轮以连续关节连接车体，轴向均为`0 1 0`。`laser_link`、`camera_link`和`imu_link`通过固定关节连接`base_link`。

车体尺寸为`0.52 × 0.36 × 0.16 m`，轮半径`0.075 m`、宽度`0.035 m`、轮距`0.36 m`。Visual负责显示，Collision参与碰撞，Inertial决定动力学。三者不一致时，画面正常也可能产生异常运动。

## 4. TF责任关系

`robot_state_publisher`根据URDF和关节状态发布模型TF；固定传感器关系进入`/tf_static`。Gazebo差速插件发布`odom -> base_footprint`，`robot_state_publisher`继续发布`base_footprint -> base_link`固定关系。后续SLAM或AMCL发布`map -> odom`。同一父子TF不得由多个节点重复发布。

预期静态关系：

| TF | 平移（m） |
|---|---|
| `base_footprint -> base_link` | `(0, 0, 0)` |
| `base_link -> laser_link` | `(0.16, 0, 0.295)` |
| `base_link -> camera_link` | `(0.20, 0, 0.335)` |
| `base_link -> imu_link` | `(0, 0, 0.235)` |

## 5. 自动测试阅读与复现

```bash
cd /home/ubuntu/ai_robot_ws
./scripts/check_environment.sh
./scripts/build.sh
source install/setup.bash
xacro src/ai_robot_description/urdf/ai_robot.urdf.xacro > /tmp/ai_robot.urdf
check_urdf /tmp/ai_robot.urdf
ctest --test-dir build/ai_robot_description -N
colcon test --packages-select ai_robot_description --event-handlers console_direct+ --ctest-args --output-on-failure
colcon test-result --test-result-base build/ai_robot_description --verbose
```

五项CTest分别验证Xacro/URDF、拓扑、物理属性、插件声明和`robot_state_publisher`。`test_gazebo_plugins.py`也包含传感器声明；L1只解释其中模型、底盘和坐标责任，M3仍需重新学习传感器断言。

仿真入口可局部验证：

```bash
colcon test --packages-select ai_robot_sim --pytest-args -k test_sim_bringup_exposes_gui_launch_argument
```

## 6. 人工观察

```bash
ros2 launch ai_robot_sim sim_bringup.launch.py gui:=true
```

另开终端运行`tf2_echo`观察上述四条TF；在RViz2中以`base_footprint`为Fixed Frame，添加RobotModel和TF。正常现象是机器人成功生成，车体、轮和传感器位置合理，模型不下沉、不翻倒、不持续抖动。

本章不运行`manual_motion_demo`，不向任何速度Topic发布消息。异常时先`Ctrl+C`停止Launch，保留日志并确认Gazebo与ROS节点退出。

## 7. 常见问题与首查位置

- Xacro失败：查XML、宏参数和安装空间是否过期；
- RobotModel为空：查`robot_description`和Fixed Frame；
- 静态TF缺失：查Joint父子关系和状态发布器；
- 模型飞散：查质量、惯量、碰撞和初始生成高度；
- 修改未生效：重新构建并加载项目Overlay。

## 8. 实体迁移与证据

实体阶段原则上保留Link/Joint语义和传感器Frame名称，但必须按实物重测尺寸、质量、惯量、安装位姿和碰撞包络。证据记录Git提交、五项测试结果、TF值、Gazebo/RViz截图、操作者和结论。

## 9. 理解检查

1. 为什么`base_footprint`不直接承载车体惯量？

4. 为什么本章不把底盘运动测试算入L1？
