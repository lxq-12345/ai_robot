# AI机器人项目学习教材管理说明

版本：v1.6

## 1. 目录定位

`learning/`保存基于本项目真实工程成果编写的正式学习教材，并纳入Git与GitHub管理。

```text
learning/
├── README.md
├── ROS2仿真机器人/
│   ├── README.md
│   ├── source/S1-1-M*/
│   ├── assets/S1-1-M*/
│   ├── html/S1-1-M*/
│   └── bks/
└── AI_Agent/                 # 阶段2后续建立
```

- `source/`：按开发单元保存版本化Markdown教材源稿；
- `assets/`：按开发单元保存教材图片资源；
- `html/`：按开发单元保存由Markdown生成的HTML阅读版；
- `bks/`：保存被替代的历史教材、旧PU材料和规则版本；
- `plan/`：规定学习目标、内容范围、练习和验收要求；
- `tests/evidence/`：保存人工操作、观察和学习检查证据。
- `tests/README.md`：测试存放、自动执行、手工执行和证据规则的统一入口。

## 2. 编号与文件名

ROS 2仿真机器人课程以开发单元`S1-1-M0`至`S1-1-M6`为一级骨架。复杂开发单元使用`L`学习子单元；`L`是`Learning Unit`的缩写。

每个学习章节是独立教材文件，名称采用：

```text
S1-1-Mx-Ly-章节序号_章节名称_v版本.md
```

例如：

```text
source/S1-1-M2/S1-1-M2-L1-01_机器人模型与Xacro_v1.0.md
```

旧`PU1`至`PU9`编号不再用于当前教材。历史文件只保存在课程`bks/`中。

## 3. 教材组成

每章教材在进入正式练习前必须具有：

1. Markdown教材源稿，必需；
2. HTML阅读版，必需；
3. 图片资源，按内容需要提供；
4. 外部参考资料链接，可选。

教材正文至少包括：所属M和L、学习目标、涉及程序包、关键文件、ROS 2对象、功能链路、测试入口、人工练习、正常现象、常见问题、安全停止、实体迁移、理解检查和项目内依据。

每个M必须设置独立的“测试与证据”学习子单元。测试教材必须讲清测试目的、风险、测试层级、代码位置、注册方式、执行入口、关键断言、预期结果、失败日志和证据要求。只列命令或只报告“通过”不构成完整测试学习。

教材不得按M复制测试实现。单包测试、公共契约、跨包集成、整机系统、手工场景和证据必须引用`tests/README.md`规定的实际位置；开源组件只学习和验证本项目采用的版本、配置、接口与组合行为，不重做其上游内部测试。

教材必须明确区分当前实现、教学解释、实体阶段内容和阶段2内容。正文必须能够离线独立阅读，不能用外部链接代替讲解。

## 4. 外部参考资料

外部资料优先使用ROS 2 Humble、Nav2、SLAM Toolbox和实际第三方组件的官方文档。每条资料使用独立编号标题，并逐行记录“来源、适用版本、用途、链接、查阅日期”，不得压缩到表格中。

旧PU1-01和PU1-02属于该格式规则建立前形成的教材；本次仅做编号和归属迁移，不追溯整理参考资料。以后正文正常升版时按当前规则统一。

## 5. 编写与学习顺序

```text
按开发计划确定当前M
→ 确定当前L和教材章节
→ 编写并审阅Markdown教材
→ 生成并验证同版本HTML
→ AI教员讲解
→ 学员完成理解检查
→ 学员亲自执行实际练习
→ 形成L结论和M学习进度
```

不得以程序包顺序替代M顺序。AI代为运行的命令只能作为演示或工程基线证据，不能替代学员人工执行。

每个M按“功能学习L → 测试与证据L → M学习结论”收尾。测试与证据L未通过时，不得将该M的学习标记为完成。

## 6. 版本与归档

- Markdown源稿是教材内容基准，HTML必须由对应Markdown生成；
- 修改正文或编号归属时提升Markdown和HTML版本，并将旧版移入课程`bks/`；
- 图片随章节归属迁移，文件名与章节前缀一致；
- 仅修正证据或状态记录时不修改教材版本；
- 教材、学习计划、证据和Git提交必须可相互追踪；
- `docs/`中的参考资料不作为当前有效教材。

### 6.1 学习计划与教材同步门槛

学习计划新增、删除、拆分、合并或实质调整M/L时，计划升版任务必须同时完成以下检查：

1. 课程README中的学习单元覆盖矩阵已经同步；
2. 每个新增或调整的L都有当前Markdown教材，或明确记录不允许进入该L正式学习；
3. 每份当前Markdown都有同版本HTML阅读版；
4. 教材引用的程序包、配置、Launch、测试和证据路径真实存在；
5. 每个M最后一个L仍为测试与证据单元；
6. 旧编号、旧顺序、旧版本和旧测试路径不再出现在当前教材入口；
7. 课程索引、当前状态和阶段备忘同步更新。

只完成计划正文和文件改名，不完成上述覆盖检查时，只能记录“学习计划已调整，教材同步未完成”，不得把新L切换为正式学习或测试目标。

## 7. 安全边界

- 教材不得授权实体机器人上电、运动、控制命令或硬件测试；
- 仿真运动使用项目已有受控入口，不手工发布`/cmd_vel`或`/cmd_vel_raw`；
- 不在ROS 2学习教材中实现或启动AI Agent；
- 发现工程缺陷时先保存证据，再按项目变更流程处理。
