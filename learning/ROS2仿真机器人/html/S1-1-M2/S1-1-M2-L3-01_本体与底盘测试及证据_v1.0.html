S1-1-M2-L3-01 本体与底盘测试及证据¶

所属开发单元：S1-1-M2 仿真本体与底盘单元
所属学习子单元：S1-1-M2-L3 本体与底盘测试及证据
章节序号：S1-1-M2-L3-01
教材版本：v1.0
测试层级：包级、契约、跨包集成、人工场景
安全边界：自动运动测试使用受控测试节点；人工运动只使用manual_motion_demo。

1. 测试目标与风险映射¶

能力 风险 证据
模型展开与拓扑 模型无法解析、TF树断裂 描述包测试
物理属性 质量/惯量/碰撞异常 物理属性测试与GUI
插件与接口 轮关节、里程计Frame错误 插件和M2契约
速度守卫 超速、命令失联不停 单元与Launch测试
底盘运动 轮速、里程计、转向方向错误 M2集成Launch
人工现象 抖动、翻倒、停止体验异常 学员观察证据

2. 代码、依赖与注册¶

描述包测试由CMakeLists.txt中的ament_add_pytest_test注册；仿真包测试由ament_python/pytest发现；工作空间契约由pytest单独执行；底盘运动Launch测试位于tests/integration/。Gazebo及插件上游内部白盒测试不复制到项目中。

3. 规定执行顺序¶

cd /home/ubuntu/ai_robot_ws
./scripts/build.sh
source install/setup.bash
ctest --test-dir build/ai_robot_description -N
colcon test --packages-select ai_robot_description ai_robot_sim --event-handlers console_direct+
colcon test-result --test-result-base build --verbose
/usr/bin/python3 -m pytest tests/contract/test_s1_m2_base_contract.py
launch_test tests/integration/test_s1_m2_base_motion.launch.py

局部命令通过后，根据当前变更风险决定是否运行./scripts/test.sh。不得用后一次全量通过隐藏前一次局部失败；失败和修复过程都应记录。

4. 关键断言解释¶

  • 模型测试：必需Link/Joint、唯一父关节、轮轴和安装位置；
  • 物理测试：正质量、有效惯量、Visual/Collision几何与基线尺寸；
  • 插件测试：左右轮、轮距轮径、/odom、Frame和轮状态；
  • 守卫单元测试：正负线速度和角速度均被限幅；
  • 守卫Launch测试：命令经/cmd_vel_raw -> /cmd_vel，超时输出零速度；
  • 运动集成：前后退轮速与里程计方向一致、转向轮速相反、最终停车。

5. 人工测试与通过标准¶

自动测试全部通过后，按M2-L2受控步骤观察Gazebo、TF、轮状态、里程计和停车。通过要求是模型无明显物理异常，前进、后退、原地转向和停车方向正确，命令链不绕过守卫，停止后速度归零。

自动测试通过不能替代GUI结论；未打开GUI时人工项记录“未执行”。

6. 失败定位与清理¶

静态断言失败查Xacro和配置；运行时无Topic查Launch和插件加载；方向错误查Joint与坐标约定；超时停车失败查守卫时钟和订阅；Gazebo启动失败先区分环境权限、资源加载和功能缺陷。测试后确认Gazebo、测试节点和ROS进程退出。

7. 证据与M2学习结论¶

证据至少包含提交号、环境、测试发现数量、每层命令和结果、关键断言解释、人工观察、停止方法、日志位置和残留风险。L1、L2和L3均有学习结论且L3通过后，才能记录M2学习完成；这不重新打开或覆盖既有M2工程验收。
