## 1. 学习目标

理解`ExecuteCapabilityTask` Action如何表达任务ID、能力、目标、超时和传感器要求，任务管理器如何校验、调用Nav2、反馈阶段、到点感知、返回结果、处理异常并对同一任务ID幂等重放。

## 2. Action契约

Goal包含`task_id`、`capability`、`target_pose`、`timeout_sec`、`require_scan`和`require_image`。Result使用固定枚举表示成功、非法、越界、导航失败、超时、取消、传感器不可用和安全触发，并返回是否重放、耗时、最小雷达距离和图像尺寸。Feedback分VALIDATING、NAVIGATING、PERCEIVING三阶段。

结构化契约让调用者得到确定状态，但它不是自然语言理解层。阶段2将来只能通过受审查接口调用，不能绕过Nav2和安全节点。

## 3. 综合执行链

```text
ExecuteCapabilityTask Goal
→ 参数、边界、并发与任务ID校验
→ Nav2 NavigateToPose
→ /cmd_vel_raw → cmd_vel_guard → /cmd_vel
→ 到点后检查/scan与/camera/image_raw
→ 固定结果枚举与数据摘要
→ 有界缓存，重复task_id直接重放
```

`m6_bringup.launch.py`组合Nav2和`capability_task_manager`，不启动AI组件。任务管理器不直接发布`/cmd_vel`。

## 4. 正常与异常行为

正常任务依次反馈校验、导航和感知，最终SUCCEEDED。非法能力或非正超时返回INVALID_TASK；目标越界返回OUT_OF_BOUNDS；Nav2失败、任务超时、取消、传感器中断和安全触发分别映射到稳定结果。并发任务被拒绝，防止多个任务争用底盘。

同一`task_id`重复请求应快速返回缓存结果，`replayed=true`，不再次导航。缓存有最大任务数，防止长期运行内存无界增长。

## 6. 常见问题、安全停止与恢复

- Goal被拒绝：查并发、Action可用和请求结构；
- 一直VALIDATING：查Nav2服务器与超时；
- 导航成功但感知失败：查消息新鲜度和Frame；
- 重放再次运动：属于严重幂等缺陷；
- 安全触发仍运动：立即判定失败并停止场景；
- 结果枚举与Action状态矛盾：查任务管理器映射。

异常时使用人工场景的安全停止，再退出Launch并确认Nav2、任务管理器和Gazebo清理。

## 7. 实体迁移与证据

实体阶段可以保留结构化Action语义，但所有能力必须重新绑定实体安全、诊断和准入条件。证据记录Goal、反馈、Action状态、Result、传感器摘要、重放耗时、运动观察和日志。

## 8. 理解检查

1. `ExecuteCapabilityTask`为什么不是AI接口层的完整实现？
2. 任务管理器为什么仍通过Nav2导航？
3. `replayed=true`应同时满足什么运动条件？
4. Action状态和业务结果枚举分别表达什么？
5. 为什么缓存必须有界？
