## 1. 能力—风险—测试映射

| 能力 | 风险 | 测试 |
|---|---|---|
| 插件声明 | Topic、Frame、频率或尺寸配置错误 | `test_gazebo_plugins.py` |
| 公共参数 | 模型与诊断基线漂移 | `test_s1_m3_sensor_contract.py` |
| 运行数据 | Topic不发布、字段无效 | `test_s1_m3_sensors.launch.py` |
| 场景一致性 | 数据虽合法但与画面不符 | M3 GUI人工场景 |

本项目不复制Gazebo传感器插件的上游算法测试，只验证采用版本、配置、接口和组合行为。

## 2. 测试注册与执行

模型插件测试随`ai_robot_description`由CTest注册；契约pytest和跨包Launch测试由工作空间管理。执行顺序：

```bash
cd /home/ubuntu/ai_robot_ws
./scripts/build.sh
source install/setup.bash
colcon test --packages-select ai_robot_description --ctest-args --output-on-failure
colcon test-result --test-result-base build/ai_robot_description --verbose
/usr/bin/python3 -m pytest tests/contract/test_s1_m3_sensor_contract.py
launch_test tests/integration/test_s1_m3_sensors.launch.py
```

自动测试通过后，再执行`tests/scenario/S1-1-M3传感器GUI观察说明.md`。

## 3. 关键断言解释

- 雷达：`laser_link`、360采样、正负角、0.12/8.0 m量程；
- 图像：`camera_link`、640×480、受支持编码、非空数据；
- CameraInfo：Frame和尺寸与图像一致；
- IMU：`imu_link`、协方差有效、方向/角速度/加速度为有限值；
- 编码器：左右轮关节均存在，位置和速度数组完整；
- 诊断契约：频率下限和缺失/陈旧消息规则存在。

断言只检查收到的样本，不直接证明长时间频率稳定；GUI也不能精确证明消息字段。两类证据共同使用。

## 4. 失败定位

静态插件断言失败查Xacro；参数契约失败查YAML与模型同步；所有Topic缺失查Gazebo启动；单一Topic缺失查对应插件；Frame错误查`frame_name`和固定TF；频率低先查仿真实时率和资源负载，再查更新率；GUI不一致查传感器位姿和场景。

## 5. 人工证据与停止

人工证据应包含Gazebo和RViz截图、Topic字段摘要、受控运动前后现象、停止方法和操作者。自动测试未通过时不得开始GUI验收；只执行自动测试时GUI结论必须为“未执行”。

异常时先停止受控运动，再停止GUI与Launch；保存首个失败，不通过重启次数掩盖稳定性问题。
