## 1. 学习目标

本章学习测试如何从源码变成colcon可发现的正式测试。学员需要找到测试依赖、注册位置、执行入口和结果文件，并区分函数单元测试、同进程节点测试、进程级Launch测试、接口契约和目录契约。

## 2. 五包注册机制

| 包 | 构建类型 | 注册位置 | 代表测试 |
|---|---|---|---|
| `ai_robot_cpp_example` | `ament_cmake` | `CMakeLists.txt` | GTest、Launch测试 |
| `ai_robot_py_example` | `ament_python` | `setup.py`、pytest | Python函数、正式进程Launch |
| `ai_robot_interfaces` | `ament_cmake`＋rosidl | `CMakeLists.txt` | 接口生成，契约在工作空间 |
| `ai_robot_description` | `ament_cmake` | `ament_add_pytest_test` | Xacro、模型、TF |
| `ai_robot_sim` | `ament_python` | pytest发现 | 速度守卫、入口 |

`package.xml`中的`test_depend`只声明依赖；没有CMake或pytest发现机制，测试文件仍可能不被`colcon test`执行。

## 3. 注册与发现检查

```bash
cd /home/ubuntu/ai_robot_ws
rg -n "test_depend|BUILD_TESTING|ament_add|pytest|launch_test" \
  src/*/package.xml src/*/CMakeLists.txt src/*/setup.py src/*/setup.cfg
colcon list
ctest --test-dir build/ai_robot_cpp_example -N
ctest --test-dir build/ai_robot_description -N
```

检查五包是为了理解边界；本章不把描述包和仿真包的全部功能测试算作M1结论。

## 4. 正式执行范围

```bash
colcon test --packages-select ai_robot_cpp_example ai_robot_py_example
colcon test-result --test-result-base build --verbose
/usr/bin/python3 -m pytest tests/contract/test_interface_baseline.py
bash tests/test_workspace_layout.sh
```

必要时复现M1最小节点集成：

```bash
source install/setup.bash
launch_test tests/integration/test_s1_m1_minimal_nodes.launch.py
```

## 5. 关键断言边界

- `StatusFormatter`只验证纯函数格式；
- 同进程节点测试验证节点名称、QoS和发布行为，但不是跨进程端到端；
- 包内Launch测试启动正式可执行程序，由独立测试端观察日志或Topic；
- `test_interface_baseline.py`读取公共YAML，证明名称和QoS契约，不证明运行数据；
- 目录契约证明文件责任，不证明机器人能力；
- `test_s1_m1_minimal_nodes.launch.py`证明两个示例进程启动、报告就绪并干净退出。

## 6. 失败定位

发现数量不符先查构建目录是否对应当前源码，再查注册语句和`test_depend`。测试进程启动但无消息时，依次查可执行安装、节点名、Topic、QoS、超时和Shutdown。接口契约失败先查配置与规划是否同步，不直接改测试期望迎合错误实现。

## 7. 安全与证据

本章只运行非运动示例节点和静态契约，不启动Gazebo运动，不操作实体机器人。证据记录发现命令、测试数量、断言分类、失败首查位置和操作者。AI预跑不能替代学员亲自执行。

## 8. 理解检查

1. `test_depend`与测试注册有什么区别？
2. 同进程测试和进程级Launch测试分别能证明什么？
3. 为什么接口YAML测试通过不代表Topic正在发布？
4. 为什么五包都要检查，但M2至M6测试不能算进M1完成度？
5. 哪些证据满足后才能形成M1学习结论？
