# U01 T01-01环境检查

版本：1.0；日期：2026-10-09。仅适用于本机AU9 Gazebo/Nav2，不用于实体或跨主机部署。

## 启动和查询

在项目根目录的图形终端执行`bash scripts/start_au9_manual_nav2.sh`。该入口加载本机UDP/loopback Fast DDS配置，停止当前ROS域的旧CLI发现缓存，再启动Gazebo/RViz/Nav2。只有在没有既有仿真进程时才启动；不得为了测试关闭用户会话。

其他查询终端均先执行：

```bash
cd /home/ubuntu/ai_robot_ws
source scripts/au9_sim_environment.sh
```

这会加载ROS/安装环境并设置rmw_fastrtps_cpp、ROS_LOCALHOST_ONLY=1和项目Fast DDS配置。它只影响当前终端及后代，不修改系统配置，不删除共享内存文件。不能把本机loopback配置用于实体或远程机器人。

等待导航和定位Lifecycle Manager均报告Active，再运行：

```bash
/usr/bin/python3 tests/helpers/u01_readiness_probe.py --output log/U01_readiness.json
ros2 action list -t
ros2 lifecycle get /controller_server
ros2 lifecycle get /map_server
```

只读探针共26项：4个生命周期、8个时间参数、5个Action服务端、3段TF、仿真时钟及5组话题端点。逐项有界等待，失败即结束并写JSON，不发目标、规划请求或速度命令。CLI初次node list可以在发现收敛前只显示部分节点，不以一次列表代替直接服务/Action就绪核验。Humble本机`ros2 action list`不支持`--no-daemon --spin-time`，不得使用该组合；需要绕过daemon时用直接ActionClient探针。

检查真实端点：controller/behaviors→`/cmd_vel_raw`→velocity_smoother→`/cmd_vel`→guard→`/cmd_vel_safe`→底盘；guard必须是safe唯一发布者。航点话题为`/waypoint_path` Path，Reliable/Volatile。查看RViz Global Status及相关显示，保存本次窗口截图。

## 结束与通过条件

仅关闭本次创建的会话：`bash scripts/stop_au9_manual_nav2.sh`。检查完整Launch日志，无服务响应超时、标记不存在错误、process死亡或超时升级；停止入口返回0不能单独证明所有进程优雅退出。核对后端、GUI、导航进程和11345端口已释放。

全部26项通过、所需Action和生命周期可查询、RViz状态正常、无控制链归属冲突，才能记录T01-01通过。粒子云显示加载过程中可先产生临时Reliable订阅，再应用已保存Best Effort配置；警告若仅启动出现、最终端点匹配且显示正常，记录为初始化提示。持续不匹配/显示失败必须判未通过。

本流程不代替T01-02单目标导航、T01-03人工航点发布或T01-04运动取消/停车测试；也不代表U01指标已冻结或AU9/Gate通过。
