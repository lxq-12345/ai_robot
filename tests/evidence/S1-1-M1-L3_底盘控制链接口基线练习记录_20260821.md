## 2. 检查链路

```text
/cmd_vel -> 底盘执行 -> /odom -> odom->base_link
```

## 3. 保持

实体阶段保持`/cmd_vel`这个Topic名称不变；
保持`/cmd_vel`使用`geometry_msgs/msg/Twist`消息类型；
保持`/odom`这个Topic名称不变；
保持`/odom`使用`nav_msgs/msg/Odometry`消息类型；
保持`odom->base_link`这个TF关系的语义不变；
保持上层导航、安全节点和任务链继续通过这些接口理解底盘运动状态。

## 4. 替换

仿真阶段的Gazebo差速插件需要替换为实体底盘驱动；
实体底盘驱动需要连接MCU通信、电机驱动和真实编码器反馈；
`/odom`和`odom->base_link`不再由Gazebo插件产生，而应由实体底盘驱动或状态估计节点根据真实编码器和传感器数据产生；
具体实现可以是`ros2_control`硬件接口、厂商ROS 2驱动，或项目自定义底盘驱动节点。

## 5. 新增验证

实体阶段需要验证左右轮方向是否正确；
验证编码器正负号和计数比例是否正确；
验证真实轮径、轮距、减速比是否准确；
验证速度上限、加速度限制和制动距离是否安全；
验证`/odom`的方向、尺度和协方差是否合理；
验证`odom->base_link`是否只有一个发布者；
验证命令超时后是否停车；
验证MCU通信断开后是否停车；
验证硬件急停是否有效；
验证软件零速度命令不能替代硬件急停。
