S1-1-M5-L2-01 已有地图定位¶

所属开发单元：S1-1-M5 SLAM、定位与Nav2
所属学习子单元：S1-1-M5-L2 已有地图定位
章节序号：S1-1-M5-L2-01
教材版本：v1.0
涉及组件：Map Server、AMCL、Lifecycle Manager、Gazebo仿真
学习边界：定位使用项目基准地图；实体地图与定位精度另行验证。

1. 学习目标¶

理解地图服务器如何发布静态地图，AMCL如何结合地图、扫描、里程计和初始位姿估计机器人位置，以及map -> odom为何由定位组件发布。学员应能区分“地图加载成功”和“定位已经建立”。

2. 定位链路¶

地图YAML/PGM → map_server → /map
/map + /scan + odom/TF + /initialpose
→ AMCL粒子估计
→ map -> odom

config/amcl_sim.yaml固定map、odom、base_link和/scan，使用差速运动模型，粒子数100至500。localization_bringup.launch.py启动基础仿真、地图服务器、AMCL和生命周期管理器。

3. 初始位姿与粒子估计¶

AMCL不知道机器人在地图中的绝对起点，需要初始位姿和协方差。初始位姿应在可通行区域，方向与仿真一致。粒子逐步收敛后，map -> odom把全局地图坐标与局部连续里程计连接起来。

错误初始位姿、地图与场景不一致、扫描Frame错误或机器人静止缺少观测变化，都可能导致收敛慢或错误定位。

4. 自动测试¶

tests/integration/test_s1_m5_localization.launch.py验证地图重载、map Frame、初始位姿注入和AMCL发布map -> odom。

cd /home/ubuntu/ai_robot_ws
./scripts/build.sh
source install/setup.bash
launch_test tests/integration/test_s1_m5_localization.launch.py

测试通过说明项目组合链可建立定位，不证明所有初始位姿和环境变化下的精度。

5. 人工观察¶

启动ros2 launch ai_robot_sim localization_bringup.launch.py gui:=true，在RViz2加载Map、LaserScan、RobotModel、TF和PoseArray；使用RViz2的2D Pose Estimate设置初始位姿。正常现象是地图加载，粒子围绕合理位姿收敛，雷达轮廓与地图墙体对齐，map -> odom出现且连续。

6. 常见问题、安全停止与恢复¶

  • 地图为空：查YAML路径、图像和生命周期；
  • 无map -> odom：查AMCL状态、初始位姿、扫描和TF；
  • 粒子不收敛：查初始位姿、地图/世界一致性和扫描；
  • 定位跳变：查里程计、时间、噪声和重复TF；
  • 方向反转：查初始四元数和坐标约定。

本章不下达导航目标。异常时停止Launch并保存地图、TF和AMCL日志。不得把仿真定位精度外推到实体机器人。

7. 证据与实体迁移¶

证据记录地图资源、初始位姿、粒子与雷达对齐截图、TF、测试结果和失败首查。实体阶段必须用实体地图或受控迁移地图，重新标定雷达与里程计并测量重复定位精度。

8. 理解检查¶

  1. 地图服务器和AMCL分别负责什么？
  2. 初始位姿为什么包含协方差？
  3. /map存在为什么仍可能没有定位？
  4. 谁发布map -> odom，为什么SLAM和AMCL不能同时负责？
  5. 粒子收敛但雷达与墙不对齐说明什么？
