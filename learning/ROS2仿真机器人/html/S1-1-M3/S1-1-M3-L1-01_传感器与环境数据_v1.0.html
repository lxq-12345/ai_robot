S1-1-M3-L1-01 传感器与环境数据¶

所属开发单元：S1-1-M3 仿真传感器单元
所属学习子单元：S1-1-M3-L1 传感器与环境数据
章节序号：S1-1-M3-L1-01
教材版本：v1.0
涉及程序包：ai_robot_description、ai_robot_sim及Gazebo ROS传感器插件
安全边界：GUI运动观察只使用项目受控演示入口，不直接发布速度Topic。

1. 学习目标¶

理解激光雷达、相机、IMU和轮关节状态如何由模型与Gazebo生成，消息中的时间戳、Frame、尺寸、范围和QoS如何与场景及TF对应。Topic存在只是第一层证据，消息有效且能转换到base_link才形成可用数据链。

2. 传感器对象与接口¶

对象 Topic 消息 Frame 设计频率
激光雷达 /scan sensor_msgs/LaserScan laser_link 10 Hz
相机图像 /camera/image_raw sensor_msgs/Image camera_link 10 Hz
相机参数 /camera/camera_info sensor_msgs/CameraInfo camera_link 10 Hz
IMU /imu/data sensor_msgs/Imu imu_link 50 Hz
轮状态 /joint_states sensor_msgs/JointState 关节名 50 Hz

静态定义位于Xacro，公共参数位于config/sim_sensors.yaml，诊断阈值位于config/sim_sensor_diagnostics.yaml。运行数据由Gazebo插件发布。

3. 数据有效性¶

雷达应有360个采样，角度覆盖机器人周向，量程0.12–8.0 m；相机应为640×480且有非空数据；CameraInfo尺寸应与图像一致；IMU数值应为有限值且方向协方差可用；JointState必须同时含左右轮名称、位置和速度。

传感器通常使用best-effort、volatile的sensor-data QoS，降低实时数据积压。用不兼容QoS订阅时可能“Topic存在但收不到消息”。

4. 自动测试阅读与局部复现¶

插件静态声明位于src/ai_robot_description/test/test_gazebo_plugins.py；运行数据由tests/integration/test_s1_m3_sensors.launch.py检查；公共参数和诊断规则由tests/contract/test_s1_m3_sensor_contract.py检查。

本章可在正式GUI练习前执行M3自动前置：

cd /home/ubuntu/ai_robot_ws
./scripts/build.sh
source install/setup.bash
/usr/bin/python3 -m pytest tests/contract/test_s1_m3_sensor_contract.py
launch_test tests/integration/test_s1_m3_sensors.launch.py

完整断言解释和M3证据汇总留给L2。

5. GUI与CLI观察¶

按tests/scenario/S1-1-M3传感器GUI观察说明.md启动Gazebo和RViz2。使用ros2 topic list、ros2 topic info --verbose、ros2 topic hz和一次消息查看确认接口；在RViz2显示LaserScan、Image或RobotModel/TF。

正常现象是雷达轮廓与障碍物一致、图像与Gazebo视角一致、IMU和轮状态持续更新、传感器Frame能转换到base_link。需要运动观察时只运行ros2 run ai_robot_sim manual_motion_demo。

6. 常见问题、安全停止与恢复¶

  • Topic缺失：查插件加载、Launch和传感器always_on；
  • 有Topic无数据：查QoS、仿真是否暂停和插件日志；
  • Frame错误：查Xacro插件frame_name和TF；
  • 图像为空或尺寸不符：查相机插件和编码；
  • IMU含NaN：查插件、时间和物理状态；
  • JointState缺轮：查关节状态插件的关节列表。

停止时先等待受控演示停车，按Ctrl+C退出观察和Launch，确认Gazebo节点退出。不得把仿真GUI操作扩展为实体设备测试。

7. 实体迁移与证据¶

实体阶段保留Topic和Frame语义，替换Gazebo插件为驱动，并新增标定、时间同步、真实噪声、遮挡和断线诊断。证据记录自动前置、Topic/QoS、消息字段、GUI截图、操作者和待补问题。

8. 理解检查¶

  1. Topic存在为什么不能证明传感器可用？
  2. LaserScan的Frame和量程分别说明什么？
  3. CameraInfo为什么必须与图像配套？
  4. JointState为什么归入传感器学习？
  5. QoS不兼容会表现为什么现象？
