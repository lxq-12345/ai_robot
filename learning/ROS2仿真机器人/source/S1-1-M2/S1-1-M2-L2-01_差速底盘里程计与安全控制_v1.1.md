## 1. 学习目标

理解差速运动学、轮速方向、速度命令链、里程计、TF、限速、命令超时和扫描超时安全。学员应能从输入命令沿节点和Topic追踪到底盘反馈。

## 2. 控制与反馈链

```text
manual_motion_demo或Nav2
→ /cmd_vel_raw
→ cmd_vel_guard（限速、命令超时、可选扫描新鲜度）
→ /cmd_vel
→ Gazebo差速插件
→ 左右两侧四轮运动
→ /joint_states、/odom、odom -> base_footprint -> base_link
```

直行时四个轮关节同向，原地转向时左侧轮组与右侧轮组方向相反。里程计位置和姿态是底盘运动估计，TF为其他组件提供坐标转换；两者方向和时间必须一致。

## 3. 参数与安全规则

`config/sim_base.yaml`限定线速度`0.35 m/s`、角速度`1.20 rad/s`、命令超时`0.50 s`、扫描超时`0.75 s`。`cmd_vel_guard`只使用线速度x和角速度z，并在命令过期或要求扫描而扫描失效时发布零速度。

软件停车是仿真安全机制，不是实体硬件急停。实体阶段还需要电机使能、硬件急停、看门狗和现场保护。

## 4. 代码与局部测试

## 5. 人工练习

终端A：

```bash
source /home/ubuntu/ai_robot_ws/install/setup.bash
ros2 launch ai_robot_sim sim_bringup.launch.py gui:=true
```

终端B先观察`/odom`和`/joint_states`，再由学员运行唯一允许的演示入口：

```bash
source /home/ubuntu/ai_robot_ws/install/setup.bash
ros2 run ai_robot_sim manual_motion_demo
```

正常现象：前进和后退时四个轮关节同向，原地转向时左侧轮组与右侧轮组反向；每段后速度归零；`/odom`位置或偏航方向与画面一致；演示结束后机器人停止。

## 6. 停止与异常处理

先等待演示自带停车段；异常时在演示终端按`Ctrl+C`，观察守卫在超时后输出零速度，再在Launch终端按`Ctrl+C`。若机器人未停，测试结论立即记为未通过，保存`/cmd_vel_raw`、`/cmd_vel`、`/odom`和日志证据。

常见首查：不动查Topic连接和扫描要求；方向错查轮轴、四个轮关节与插件轮组配置；里程计错查轮距轮径和Frame；不停查守卫定时器、命令时间戳和下游连接。

## 7. 实体迁移与证据

实体底盘保持上层速度和里程计接口，Gazebo插件替换为驱动与控制器。轮径、轮距、编码器比例、加速度和制动距离必须实测。证据记录自动前置结果、操作步骤、轮速/里程计观察、停止方法、截图或日志和结论。

## 8. 理解检查

1. 为什么Nav2和人工演示都应进入`/cmd_vel_raw`？
2. 原地左转时左右两侧轮组速度方向应怎样？
3. `/odom`消息与`odom -> base_footprint -> base_link`TF链分别服务什么？
4. 命令超时和扫描超时有什么区别？
5. 为什么软件零速度不能替代实体急停？
