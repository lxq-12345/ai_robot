# waypoint_navigation 开发与测试项目计划

- 版本：1.2
- 日期：2026-10-04
- 配套规范：plan/waypoint_navigation_需求与设计规范_v1.1.md
- 状态：待实施；本文不表示测试已经通过
- 目标：RViz2 航点提交 → 配置校验去重 → 用户请求规划并预览 → 用户请求执行 → 按序实际经过航点、监视、取消及可靠配置持久化；当前候选设计采用Nav2 ComputePathThroughPoses与FollowPath，R00-C冻结最终实现
- 范围：优先在现有 ROS 2/Nav2 仿真环境实施，实体测试另行授权

## 1. 执行与验收规则

每个执行单元必须在本单元内完成“开发 → 对应层级测试 → 缺陷修复 → 回归 → 验收记录”，不能把测试全部推迟到最后。依赖单元未验收通过，不进入依赖它的后续单元。失败、跳过和受阻均不能记为通过。

每单元必须交付：代码或配置、操作步骤、可复现测试、预期与实际结果、日志或其他证据、未解决问题清单。模拟测试只证明对应逻辑，不替代真实 Nav2 仿真集成验证。实际指标及阈值在 U01 冻结；测试期间修改阈值必须记录理由并重测相关用例。

若R00-C确认需要自研或薄适配，实施代码按冻结方案进入现有工作空间；暂定包名`src/waypoint_navigation`。单包测试放在责任包内test；跨包集成、系统场景和证据遵循工作空间`tests/README.md`。本计划归属AU9新增单元，不新增M或Gate；完成本计划所有保留单元及验收，即满足用户指定的AU9新增完成边界。

每单元技术验收之后记录 Git 提交。若项目要求远端归档，必须推送并核验远端分支及提交；无法完成时标为“技术验收通过，远端归档未完成”。不自动把单元视为现有项目里程碑。

## 2. 单元依赖与阶段关口

```text
R00-A 广泛资源调研 → U01 环境基线 → R00-B 候选实测 → R00-C 复用决策与范围冻结 → U02 包与接口骨架 → U03 数据与去重
                                  ├→ U04 配置保存加载
                                  └→ U05 状态机与任务一致性
U04 + U05 → U06 环境检查与异步规划 → U07 预览与执行前检查
U07 → U08 FollowPath 执行 → U09 取消与故障处理
U08 + U09 → U10 终端报告与航点进度
全部单元 → U11 综合验收 → U12 交付与复现验收
```

关口 R：R00-A/B/C 全部验收通过，已确认现成能力、自研缺口及最终设计；未通过不得开始 U02–U10 的功能实现。关口 A：U01–U05 通过，配置和任务模型可靠；关口 B：U06–U07 通过，用户请求时能够规划和预览，但提交或加载航点均不自动规划或运动；关口 C：U08–U10 通过，具备受控执行、按序实际经过航点和可观察故障处理；关口 D：U11–U12 通过，第一版可交付。本项目纳入AU9，不新增工程里程碑或Gate。

## 2A. 开发前置：开源或免费资源调研、实测与复用决策

原则：先验证现成软件，再决定自研范围。检索不能只限定 waypoint_path_navigator 名称，还需覆盖 WayPath、waypoint manager、route manager、mission planner、path follower、RViz path editor、Nav2 FollowPath、NavigateThroughPoses、FollowWaypoints 等关键词。功能满足需求但接口不同的项目也进入候选，评估适配成本，不因名字不同直接排除。

本次计划修订仅定义执行单元，不表示调研、候选构建或集成验收已经完成。此前网上检索结论属于候选发现证据，不能替代本计划的实际测试。

### R00-A：广泛资源调研与候选初筛

**执行内容**：

- 搜索 GitHub、GitLab、ROS Index/发行版包索引、Nav2 官方源码及示例、机器人厂商资源、Hugging Face Models/Spaces/Datasets；结合论文、ROSCon 和论坛线索追溯原始源码。
- 优先检查已安装 Nav2 RViz 面板、现有 Waypoint Plugin 的保存加载，以及 Simple Commander，避免重复实现已有功能。
- 建立候选表，记录源码 URL、版本/提交、许可证、支持发行版、依赖、维护证据、功能及接口。免费闭源方案另列：核对免费条款、离线运行和部署限制；不能视为开源。

### R00-B：候选构建与现有仿真集成测试

前置：R00-A 和 U01 通过。候选固定版本，在独立评估工作空间或可清理的隔离环境中测试，避免覆盖现有稳定配置。不得照搬候选项目中不适用于当前机器人的启动或控制命令。

**执行内容**：对入围路线构建安装，尝试接入现有地图、TF、Nav2；评估与 `/waypoint_path` 的数据适配。允许薄适配原型，但不先实现完整新应用。记录所有改动及原型是否拟保留。候选按同一固定需求比较，现成资源不能通过降低“手动规划与执行、按序实际经过每个航点、中途不停靠、失败不跳点或自动重规划”等需求来取得通过结论。

**测试**：

- TR-B01：依照记录步骤安装构建，接口、发行版与依赖符合实际；第二次可复现。
- TR-B02：两个航点与转弯/绕墙场景，从现有 RViz2 输入到导航结果验证；无法直接接入时测试最小适配，说明原因。
- TR-B03：配置保存加载往返、地图关联及加载是否触发运动。
- TR-B04：航点提交、用户请求规划、预览和用户请求执行分离；确认真实规划与执行Action名称，可以比较FollowPath、NavigateThroughPoses、FollowWaypoints或NavigateToPose，不以界面名称代替核验。候选的Action不同不自动意味着满足同一需求。
- TR-B05：重复发布/启动、执行中改配置、取消、不可达目标、服务器不可用和重启行为。
- TR-B06：检查日志、反馈、错误信息及航点经过报告是否有依据。
- TR-B07：检查退出清理、是否直接发布速度、是否与其他导航入口冲突，以及需增加的安全措施。

**验收**：每条入围路线的需求项记录为原生支持、薄适配可测、缺失待开发、失败或受阻；不要求候选本身满足全部需求才完成评估，但不得把未测能力记为通过。原则上完成两条路线实测；缺少候选或外部条件受阻时，记录限制，不以未验证项目作为生产依赖。至少一条路线具备真实仿真导航成功证据，才能进入最终选型；最终方案仍须覆盖全部固定需求。

- TR-C01：每项固定需求映射到选定组件、薄适配或自研模块，并关联测试证据；特别核对手动规划与执行、实际按序经过航点和失败不跳点。

## 3. U01：环境基线与验收指标

**开发内容**：核对 ROS_DISTRO/Nav2 版本、本机 Action 字段、规划器和控制器 ID、TF、仿真时间、地图身份和速度链。记录启动命令、地图和配置版本。制定验收指标表及阈值，包括中途航点位置偏差、终点位置与朝向容差、规划等待、路径年龄、起点偏移、无法通过航点的失败判定及取消响应。

**测试**：

- T01-01：正常启动后检查生命周期、Action、TF和话题 QoS，实际结果与基线一致。
- T01-02：RViz2 单目标导航在开放区域和转弯场景各完成一次，记录终点误差及结果。
- T01-03：发布两个航点，确认 Path 的顺序、参考系、姿态和实际发布触发行为。
- T01-04：确认仿真 use_sim_time 一致；验证停止导航和独立停止手段可用。

**验收**：基础导航可用；未确认项有明确结论；冻结中途位置偏差、终点位置/朝向、规划等待、取消响应、路径年龄、起点偏移、无法通过航点的判定和日志频率等指标。任何基础导航故障先修复，不由新脚本掩盖。

**证据**：版本表、命令输出、配置摘要、导航日志、指标基线。

## 4. U02：Python 包与外部接口骨架

**开发内容**：建立模块目录、ROS 包元数据、console entry point、launch、参数文件；建立订阅、服务和状态发布骨架；默认不启动运动。

**测试**：

- T02-01：colcon 构建、安装后从任意目录通过 ros2 run/launch 启动成功。
- T02-02：实际 topic/service 名、类型与规范一致，命名空间和重映射生效。
- T02-03：无配置时 plan/execute 返回明确拒绝；无任务 cancel 返回一致状态。
- T02-04：启动、退出和异常参数不会创建规划或执行Action目标；退出后无遗留节点。
- T02-05：节点启动、首次有效Publish、重复Publish和加载配置均不创建规划或执行Action目标；无手动plan时无有效规划路径预览。

**验收**：入口简洁，模块可导入；接口可查询；参数有类型与边界检查；执行入口默认受控。

**证据**：构建日志、接口清单、服务调用结果、测试报告。

## 5. U03：配置模型、校验与幂等去重

**开发内容**：实现有序航点模型、header 补齐策略、四元数归一化、确定性量化与指纹、配置版本和限频日志。

**测试**：

- T03-01：正常两个点转换正确，顺序保留，空单点 frame 按父 header 处理。
- T03-02：空列表、超量点、NaN/Inf、零四元数、非法参考系被拒绝，旧有效配置保留。
- T03-03：不同时间戳、q/-q、规定范围内浮点误差生成相同指纹。
- T03-04：航点顺序、坐标超量化边界、参考系或地图身份变化产生新配置。
- T03-05：同配置连续提交100次，仅一次有效更新，不产生重复规划、执行和写文件。
- T03-06：量化边界与 w≈0 姿态的标准化结果稳定、可复现。
- T03-07：首次有效Publish只更新配置，不调用规划Action；不同有效Publish使旧规划失效，仍等待用户手动plan；航点位置与朝向按顺序保留。

**验收**：有效输入可用，无效输入不污染配置；去重语义与规范一致；版本只在有效内容改变时增加。

**证据**：自动化测试结果、指纹样例、有效处理计数及重复提交日志。

## 6. U04：YAML 保存与加载

**开发内容**：实现 schema、安全解析、文件边界检查、原子写入、地图匹配、加载后航点配置显示；加载结果经过 U03 校验。加载不得自动生成规划导航路径；旧规划预览须失效。

**测试**：

- T04-01：保存加载往返后配置语义与指纹一致。
- T04-02：相同内容同路径避免冗余写入；新路径仍写入；外部修改文件后正确处理。
- T04-03：不存在文件、损坏 YAML、未知 schema、非法字段、超大文件报告错误，内存配置保留。
- T04-04：写入故障或替换失败不损坏原文件；临时文件处理可追溯。
- T04-05：地图身份不匹配阻止执行；未知身份按既定策略报告。
- T04-06：加载配置只恢复和显示航点，不创建规划或运动目标；旧规划与预览失效；执行中加载进入待处理配置，当前任务结束后仍须等待新的手动plan与execute。

**验收**：持久化可靠，无隐式运动；所有文件故障有明确原因；保存目录和权限错误可理解。

**证据**：YAML 样例、文件故障测试、往返对比及服务结果。

## 7. U05：任务状态机与异步一致性

**开发内容**：实现任务 ID、配置版本、不可变任务快照、待处理配置、串行事件协调和旧回调过滤。

**测试**：

- T05-01：正常状态链、失败链及取消链符合状态表。
- T05-02：规划中更新配置，旧结果晚到不能覆盖新配置或进入 READY。
- T05-03：执行中相同配置忽略，不同配置保留待处理，当前快照不变。
- T05-04：并发重复 execute 只有一个目标；迟到反馈与结果不能修改另一任务。
- T05-05：取消后迟到成功结果按明确策略处理，不触发下一任务。
- T05-06：重启后不恢复运动；待处理配置只在适当终态提升。
- T05-07：规划中重复plan、执行中plan、任务失败后待处理配置提升均按明确状态转换处理；不生成并发规划/执行目标，不自动接管下一任务。

**验收**：所有状态变化由统一协调者处理；无双目标、旧结果覆盖和自动接管；状态模拟测试覆盖关键竞态。

**证据**：状态转换表、自动化事件序列、任务计数与回调过滤日志。

## 8. U06：环境检查与异步路径规划

**开发内容**：检查 Action、TF、ROS 时钟和服务器就绪；获取当前位置；调用 ComputePathThroughPoses；封装版本适配、超时和规划取消。

**测试**：

- T06-01：开放区域及绕墙规划成功，起点衔接机器人当前位置，规划路径按序进入U01冻结的各航点位置范围；中途朝向不作为到达条件。
- T06-02：不可达点、空结果、服务器拒绝均产生明确失败，无执行Action目标。
- T06-03：服务器不存在、TF 缺失、时间不一致按超时终止，不阻塞其他接口。
- T06-04：规划中 cancel 或新配置使旧结果失效，实际 Nav2 回调与状态测试一致。
- T06-05：订阅与状态服务在规划期间仍响应，不在回调中长时间阻塞。
- T06-06：收到或加载航点后无规划目标；只有用户请求plan才调用规划Action，规划成功只发布预览，不发送执行目标。

**验收**：真实 Nav2 规划集成通过；规划失败不运动；错误包含阶段及原始信息。

**证据**：Action 记录、路径样本、仿真截图、TF/超时日志。

## 9. U07：路径预览与执行前有效性

## 13. U11：端到端综合回归与第一版验收

**开发内容**：修复集成缺陷，冻结默认配置，整理全链路场景。不得以综合测试代替前面单元测试。

**测试场景**：

1. 新启动 → RViz2 两点提交 → 规划预览 → 显式执行 → 成功。
2. 三点转弯及墙体绕行，连续各运行至少3次。
3. 保存 → 重启 → 加载 → 重新规划 → 执行；加载期间不运动。
4. 同配置连续 Publish 100次，有效配置版本、文件写入和 Action 计数符合去重规则。
5. 规划中更新、执行中更新、重复执行，均无旧结果和任务覆盖。

7. 中途取消、服务器失联、定位异常、节点重启，状态和失败信息准确。
8. 新障碍出现，记录实际控制器结果和安全边界；允许局部避障后仍按序经过航点，不要求第一版自动重新规划。
9. 首次Publish、重复Publish、加载均不自动规划；只有手动plan才规划，只有手动execute才发送执行目标。
10. 遇障绕行后仍按序经过航点为成功候选；无法进入、漏点或乱序为失败，不能因Action成功而误报任务成功，且不自动重新规划或继续后续航点。

**验收**：全部必测场景通过；无未解决的运动控制、任务一致性或文件损坏问题；中途位置与终点位置/朝向指标符合U01；服务接收、规划结果、执行Action、实际逐点经过和停车分别留证。失败场景可复现且行为符合规范。若测试失败必须回到责任单元修复，重测受影响场景。

**证据**：综合用例表、至少3次重复运行记录、rosbag或轨迹、缺陷闭环和需求覆盖矩阵。
