# AU2 软件安装与环境检查

> 适用环境：Ubuntu 22.04、ROS 2 Humble、Gazebo Classic、RViz2  
> 对应计划：AU2

## 1 本单元定位

本项目明确使用Gazebo Classic和`gazebo_ros`，不是新版Gazebo Sim。安装时必须先确认项目基线，避免混用两套命令、插件和文件格式。

## 2 学习目标

- 识别Ubuntu、ROS 2和Gazebo版本；
- 检查Gazebo、RViz2、Nav2与项目依赖；
- 验证工作区构建、环境加载和基础启动；
- 能区分“软件未安装”和“项目环境未加载”。

## 3 版本边界

课程基线为Ubuntu 22.04和ROS 2 Humble。项目的Launch文件包含`gazebo_ros`，机器人使用`libgazebo_ros_diff_drive.so`、`libgazebo_ros_camera.so`等Gazebo Classic插件。因此教材操作以Gazebo Classic为准。

Gazebo Classic已经结束上游生命周期，但现有项目仍依赖它。课程目标是掌握并维护当前项目，不把新版Gazebo Sim的`gz sim`命令和插件名称混入本项目。后续迁移应另立任务。

## 4 安装与检查

先检查系统：

```bash
lsb_release -a
printenv ROS_DISTRO
```

检查命令与软件包：

```bash
which gazebo
which rviz2
ros2 pkg prefix gazebo_ros
ros2 pkg prefix rviz2
ros2 pkg prefix nav2_bringup
```

需要安装时，在Ubuntu 22.04和ROS 2 Humble的软件源已经正确配置的前提下使用：

```bash
sudo apt update
sudo apt install ros-humble-gazebo-ros-pkgs ros-humble-rviz2 ros-humble-navigation2 ros-humble-nav2-bringup
```

不要把密码、私钥或远程凭据写入学习证据。

## 5 项目构建与环境加载

```bash
cd /home/ubuntu/ai_robot_ws
./scripts/build.sh
source install/setup.bash
```

检查项目包：

```bash
ros2 pkg prefix ai_robot_description
ros2 pkg prefix ai_robot_sim
```

检查Launch参数：

```bash
ros2 launch ai_robot_sim sim_bringup.launch.py --show-args
```

当前项目应至少显示`gui`、`world`和`require_scan`参数。

## 6 启动验证

Gazebo GUI验证：

```bash
ros2 launch ai_robot_sim sim_bringup.launch.py gui:=true
```

RViz2验证：

```bash
rviz2
```

ROS图验证：

```bash
ros2 topic list
ros2 topic echo /clock --once
```

## 7 正常现象

- 构建脚本无失败软件包；
- Gazebo GUI能够打开并生成`ai_robot`；
- RViz2能够独立启动；
- `/clock`存在并持续更新；
- `ai_robot_sim`和`ai_robot_description`能被ROS 2找到。

## 8 常见问题与排查

### 8.1 找不到软件包

先执行：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ai_robot_ws/install/setup.bash
```

仍找不到时再判断是否未构建或未安装。

### 8.2 Gazebo有服务器但无窗口

检查是否使用`gui:=true`。后台自动测试通常只启动服务器，不弹出客户端。

### 8.3 插件加载失败

确认安装`gazebo_ros_pkgs`，并检查Xacro中的插件名称是否属于Gazebo Classic。

### 8.4 启动后残留进程

先在原终端用Ctrl+C正常结束，再检查是否仍有Gazebo或ROS节点。不要用强制清理代替正常关闭流程。
