S1-1-M2-L1-01 机器人模型、坐标系与仿真环境¶

所属开发单元：S1-1-M2 仿真本体与底盘单元
所属学习子单元：S1-1-M2-L1 机器人模型、坐标系与仿真环境
章节序号：S1-1-M2-L1-01
教材版本：v1.0
涉及程序包：ai_robot_description、ai_robot_sim
学习边界：验证模型、静态TF和仿真生成；底盘运动、里程计、限速和超时停车留给L2/L3。

1. 学习目标¶

学员应能解释Xacro如何生成URDF，Link描述什么，Joint怎样建立树，惯量与Collision为何影响物理仿真，Gazebo插件怎样把模型接到ROS 2，以及robot_state_publisher与Gazebo分别承担哪些TF责任。

2. 工程成果与关键文件¶

  • src/ai_robot_description/urdf/ai_robot.urdf.xacro：模型权威源；
  • src/ai_robot_description/CMakeLists.txt：安装模型并注册五项测试；
  • src/ai_robot_sim/launch/sim_bringup.launch.py：展开模型、启动Gazebo、状态发布器、生成实体和速度守卫；
  • config/tf_frame_baseline.yaml：TF语义和唯一发布责任；
  • src/ai_robot_description/test/：模型、物理属性、插件和TF测试。

3. 模型结构¶

base_footprint是地面投影根Link，不带惯量；固定关节连接base_link。左右轮以连续关节连接车体，轴向均为0 1 0。laser_link、camera_link和imu_link通过固定关节连接base_link。

车体尺寸为0.52 × 0.36 × 0.16 m，轮半径0.075 m、宽度0.035 m、轮距0.36 m。Visual负责显示，Collision参与碰撞，Inertial决定动力学。三者不一致时，画面正常也可能产生异常运动。

4. TF责任关系¶

robot_state_publisher根据URDF和关节状态发布模型TF；固定传感器关系进入/tf_static。Gazebo差速插件发布odom -> base_link。后续SLAM或AMCL发布map -> odom。同一父子TF不得由多个节点重复发布。

预期静态关系：

TF 平移（m）
base_footprint -> base_link (0, 0, 0)
base_link -> laser_link (0.16, 0, 0.295)
base_link -> camera_link (0.20, 0, 0.335)
base_link -> imu_link (0, 0, 0.235)

5. 自动测试阅读与复现¶

cd /home/ubuntu/ai_robot_ws
./scripts/check_environment.sh
./scripts/build.sh
source install/setup.bash
xacro src/ai_robot_description/urdf/ai_robot.urdf.xacro > /tmp/ai_robot.urdf
check_urdf /tmp/ai_robot.urdf
ctest --test-dir build/ai_robot_description -N
colcon test --packages-select ai_robot_description --event-handlers console_direct+ --ctest-args --output-on-failure
colcon test-result --test-result-base build/ai_robot_description --verbose

五项CTest分别验证Xacro/URDF、拓扑、物理属性、插件声明和robot_state_publisher。test_gazebo_plugins.py也包含传感器声明；L1只解释其中模型、底盘和坐标责任，M3仍需重新学习传感器断言。

仿真入口可局部验证：

colcon test --packages-select ai_robot_sim --pytest-args -k test_sim_bringup_exposes_gui_launch_argument

6. 人工观察¶

ros2 launch ai_robot_sim sim_bringup.launch.py gui:=true

另开终端运行tf2_echo观察上述四条TF；在RViz2中以base_footprint为Fixed Frame，添加RobotModel和TF。正常现象是机器人成功生成，车体、轮和传感器位置合理，模型不下沉、不翻倒、不持续抖动。

本章不运行manual_motion_demo，不向任何速度Topic发布消息。异常时先Ctrl+C停止Launch，保留日志并确认Gazebo与ROS节点退出。

7. 常见问题与首查位置¶

  • Xacro失败：查XML、宏参数和安装空间是否过期；
  • RobotModel为空：查robot_description和Fixed Frame；
  • 静态TF缺失：查Joint父子关系和状态发布器；
  • 模型飞散：查质量、惯量、碰撞和初始生成高度；
  • 修改未生效：重新构建并加载项目Overlay。

8. 实体迁移与证据¶

实体阶段原则上保留Link/Joint语义和传感器Frame名称，但必须按实物重测尺寸、质量、惯量、安装位姿和碰撞包络。证据记录Git提交、五项测试结果、TF值、Gazebo/RViz截图、操作者和结论。

9. 理解检查¶

  1. 为什么base_footprint不直接承载车体惯量？
  2. Visual与Collision不一致会产生什么风险？
  3. 谁发布静态传感器TF，谁发布odom -> base_link？
  4. 为什么本章不把底盘运动测试算入L1？
  5. 模型显示正常是否足以证明物理属性正确？
