# AI机器人项目学习教材管理说明

版本：v1.2

## 1. 目录定位

`learning/`保存基于本项目真实工程成果编写的正式学习教材，并纳入Git与GitHub管理。

```text
learning/
├── README.md
├── ROS2仿真机器人/
│   ├── README.md
│   ├── source/
│   │   └── PU*/
│   ├── assets/
│   │   └── PU*/
│   ├── html/
│   │   └── PU*/
│   └── bks/
└── AI_Agent/                 # 阶段 2后续建立
```

- `learning/ROS2仿真机器人/`：当前ROS 2仿真机器人课程根目录；
- `source/`：按PU保存版本化Markdown教材源稿；
- `assets/`：保存教材使用的PNG、JPG、SVG等图片资源；
- `html/`：保存由Markdown生成、供学员阅读的HTML版本；
- `bks/`：保存该课程被替代的历史教材和规则版本；
- `plan/`：规定学习目标、内容范围、练习和验收要求，不保存教材正文；
- `tests/evidence/`：保存人工操作、观察和学习验收证据，不保存教材正文。

## 2. 教材组成

每个学习章节是一个独立教材单元，文件名采用`PU序号-章节序号_章节名称_v版本.md`，例如`PU1-01_项目总体架构_v1.0.md`。每章教材在进入对应正式练习前必须形成以下内容：

1. Markdown教材源稿，必需；
2. HTML阅读版，必需；
3. 图片资源，按内容需要提供；
4. 外部参考资料链接，可选。

教材正文必须能够离线独立阅读，不得用一组外部链接代替讲解。

### 2.1 教材正文

正文至少包括：

- 学习目标和适用范围；
- 本项目采用的实际架构、程序包、节点和文件；
- ROS 2对象、接口、参数、QoS和TF；
- 关键功能链路和数据流；
- 只读检查或受控操作方法；
- 正常现象、常见问题及首查位置；
- 仿真实现与未来实体实现的对应关系；
- 术语表、学习总结和练习前理解检查；
- 项目内依据。

教材必须明确区分：

- 当前已经实现并通过工程测试的内容；
- 教学解释或概念模型；
- 后续实体阶段才会实现的内容；
- 阶段 2才会讨论的AI Agent内容。

### 2.2 外部参考资料

外部资料只在确有帮助时提供，优先使用：

- ROS 2 Humble官方文档；
- Nav2、SLAM Toolbox及实际第三方组件的官方文档；
- 官方源代码仓库、接口文档和发布说明。

每条外部资料至少记录资料名称、来源、适用版本、用途、链接和查阅日期。来源不明、版本不匹配或无法验证的内容不得列为正式参考资料。

从PU1-03及以后新建的教材开始，外部资料项不得使用Markdown表格或项目列表。每条资料采用独立编号标题，字段在标题下逐行书写：

```markdown
### 1. What is a Workspace?

**来源**：colcon官方文档

**适用版本**：colcon

**用途**：理解源码、构建、安装和日志空间

**链接**：https://colcon.readthedocs.io/en/released/user/what-is-a-workspace.html

**查阅日期**：2026-07-29
```

资料标题按`1.`、`2.`、`3.`顺序编号。字段名称统一使用“来源、适用版本、用途、链接、查阅日期”，不得把多个资料压缩到同一张表中。PU1-01和PU1-02属于本规则建立前已经完成的教材，不追溯修改；以后仅在它们因教材正文变化正常升版时，再按届时有效规范整理。

外部资料与本项目实现不一致时，以当前项目代码、配置、测试证据和有效规划为准，并在教材中说明差异。

## 3. 编写与学习顺序

每个学习章节固定按以下顺序执行：

```text
依据学习计划确定教材范围
→ 编写并审阅独立章节Markdown教材
→ 生成并验证同版本HTML阅读版
→ AI教员按章节教材讲解
→ 学员提出问题并完成理解检查
→ 学员亲自执行实际练习
→ 形成学习检查与证据
```

不得在教材尚未形成或尚未讲解完毕时，直接把正式实际练习标记为完成。AI代为运行的命令只能作为演示或工程基线证据，不能替代学员人工执行。

## 4. 版本与归档

- 当前教材文件名包含章节号和版本号，例如`PU1-01_项目总体架构_v1.0.md`；
- Markdown源稿是教材内容基准，HTML阅读版必须由对应Markdown生成，不独立修改正文；
- 修改教材正文时同时提升Markdown和HTML版本号，并将旧版移入对应课程的`bks/`；
- 仅修正学习证据或状态记录时，不修改教材版本；
- 教材版本、学习计划版本、证据记录和Git提交应可相互追踪；
- `docs/`中的网页原稿或参考资料不作为当前有效教材，也不上传GitHub。

## 5. 安全边界

- 教材不得授权实体机器人上电、运动、控制命令或硬件测试；
- 仿真运动练习必须使用项目已有受控入口，不得手工发布`/cmd_vel`或`/cmd_vel_raw`；
- 不在ROS 2学习教材中实现或启动AI Agent；
- 发现工程缺陷时先保存现象和证据，再按项目变更流程处理，不在教学过程中直接修改稳定基线。
