# R00-B候选实测复现步骤

依据：开发测试计划v1.3。仅本机仿真，不用于实体。详细预期、失败及未测项见tests/evidence/waypoint_navigation/R00-B/候选实测报告_20261009.md。A/B共享后端，串行运行；另一入口不得发送导航目标。

1. 记录当前地图、安装配置及版本，检查已有会话；已有人工会话时不接管。每个终端执行`source scripts/au9_sim_environment.sh`。
2. 经运行授权，独立终端执行`bash scripts/start_au9_manual_nav2.sh`；等待两组Lifecycle Manager报告Active，再执行只读准备探针：`/usr/bin/python3 tests/helpers/u01_readiness_probe.py --output log/R00B_reproduce/readiness.json`。这是R00-B准备，不是U01验收。
3. 从初始位置执行A真实GUI场景：`timeout 150s /usr/bin/python3 tests/helpers/r00b_candidate_probe.py --route A --scenario open --gui --output log/R00B_reproduce/A_open_gui`。GUI辅助要求记录的1500x900布局，会清除本次RViz航点；焦点或鼠标窗口检查失败即拒绝点击，不当作导航故障。自动GUI证据不替代学员人工练习。
4. B独立运动须新会话初态；执行同一命令但`--route B`。若GUI受阻，去掉`--gui`可测后端，但结果必须注明构造输入，不能冒充GUI端到端证据。
5. 串行执行`--scenario turn/wall/unreachable/cancel/input/unavailable`中的具体一个场景，每次独立output目录。`unavailable`当前只验证直接Action有界发现，Commander本身另需不存在名称空间的12秒有界外部试验。turn的A/B路线方向不同，不用于性能比较。禁止并行运行运动场景。
6. 读取result.json、轨迹和Action终态；返回成功而终点超差、漏点、没有实际运动均不能认定导航成功。原型成功不证明最终状态机、YAML、去重或路径有效性模块实现。
7. 失败后核对目标已经终态和速度为零；未知目标状态、外部timeout或Ctrl+C后执行`bash scripts/stop_au9_manual_nav2.sh`，不要仅杀客户端后启动下一目标。正常收尾也执行停止脚本，核验进程、退出码及11345端口。

用例失败按责任域处理，不扩大全工作区测试；指标不得为通过而放宽。真实安装配置可能含会话前已有未提交改动，必须与证据副本匹配。每轮测试等待上限和停止路径明确后才运行。项目正式U01仍在R00-C之后。
