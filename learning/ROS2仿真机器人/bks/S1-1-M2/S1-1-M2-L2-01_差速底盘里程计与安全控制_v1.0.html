S1-1-M2-L2-01 差速底盘、里程计与安全控制¶

所属开发单元：S1-1-M2 仿真本体与底盘单元
所属学习子单元：S1-1-M2-L2 差速底盘、里程计与安全控制
章节序号：S1-1-M2-L2-01
教材版本：v1.0
涉及程序包：ai_robot_description、ai_robot_sim
安全边界：仿真运动只使用manual_motion_demo；学员不得手工向/cmd_vel_raw或/cmd_vel发布消息。

1. 学习目标¶

理解差速运动学、轮速方向、速度命令链、里程计、TF、限速、命令超时和扫描超时安全。学员应能从输入命令沿节点和Topic追踪到底盘反馈。

2. 控制与反馈链¶

manual_motion_demo或Nav2
→ /cmd_vel_raw
→ cmd_vel_guard（限速、命令超时、可选扫描新鲜度）
→ /cmd_vel
→ Gazebo差速插件
→ 左右轮运动
→ /joint_states、/odom、odom -> base_link

直行时左右轮同向，原地转向时方向相反。里程计位置和姿态是底盘运动估计，TF为其他组件提供坐标转换；两者方向和时间必须一致。

3. 参数与安全规则¶

config/sim_base.yaml限定线速度0.35 m/s、角速度1.20 rad/s、命令超时0.50 s、扫描超时0.75 s。cmd_vel_guard只使用线速度x和角速度z，并在命令过期或要求扫描而扫描失效时发布零速度。

软件停车是仿真安全机制，不是实体硬件急停。实体阶段还需要电机使能、硬件急停、看门狗和现场保护。

4. 代码与局部测试¶

  • cmd_vel_guard.py：clamp_twist和超时逻辑；
  • test_cmd_vel_guard_unit.py：纯函数限速；
  • test_cmd_vel_guard_launch.py：正式节点、Topic与超时零速度；
  • manual_motion_demo.py：受控前进、停止、后退、停止、左右转和停止序列；
  • test_s1_m2_base_contract.py：插件、轮状态和安全参数契约。

正式完整执行留到L3；本章可阅读断言并在自动前置测试通过后进行受控观察。

5. 人工练习¶

终端A：

source /home/ubuntu/ai_robot_ws/install/setup.bash
ros2 launch ai_robot_sim sim_bringup.launch.py gui:=true

终端B先观察/odom和/joint_states，再由学员运行唯一允许的演示入口：

source /home/ubuntu/ai_robot_ws/install/setup.bash
ros2 run ai_robot_sim manual_motion_demo

正常现象：前进和后退时左右轮同向，原地转向时左右轮反向；每段后速度归零；/odom位置或偏航方向与画面一致；演示结束后机器人停止。

6. 停止与异常处理¶

先等待演示自带停车段；异常时在演示终端按Ctrl+C，观察守卫在超时后输出零速度，再在Launch终端按Ctrl+C。若机器人未停，测试结论立即记为未通过，保存/cmd_vel_raw、/cmd_vel、/odom和日志证据。

常见首查：不动查Topic连接和扫描要求；方向错查轮轴、左右关节与插件；里程计错查轮距轮径和Frame；不停查守卫定时器、命令时间戳和下游连接。

7. 实体迁移与证据¶

实体底盘保持上层速度和里程计接口，Gazebo插件替换为驱动与控制器。轮径、轮距、编码器比例、加速度和制动距离必须实测。证据记录自动前置结果、操作步骤、轮速/里程计观察、停止方法、截图或日志和结论。

8. 理解检查¶

  1. 为什么Nav2和人工演示都应进入/cmd_vel_raw？
  2. 原地左转时两轮速度方向应怎样？
  3. /odom消息与odom -> base_linkTF分别服务什么？
  4. 命令超时和扫描超时有什么区别？
  5. 为什么软件零速度不能替代实体急停？
